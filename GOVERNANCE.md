# Dragon Project Governance

This document describes the governance model for the Dragon programming language project.

## Project Roles

### Maintainers
Maintainers have commit access to the repository and are responsible for:
- Reviewing and merging pull requests
- Setting technical direction
- Maintaining code quality
- Managing releases
- Enforcing the code of conduct

### Contributors
Anyone who contributes code, documentation, tests, or other valuable contributions to the project.

### Users
Anyone who uses the Dragon programming language.

## Decision Making

### Technical Decisions
Technical decisions are made by maintainers through consensus. When consensus cannot be reached, a majority vote among maintainers is used.

### Language Changes
Changes to the Dragon language specification follow the language change process documented in `governance/LANGUAGE_CHANGE_PROCESS.md`.

### Project Direction
Overall project direction is set by maintainers based on community feedback and the project's goals.

## Communication

### Primary Channels
- GitHub Issues: For bug reports, feature requests, and discussions
- GitHub Discussions: For general conversation and questions
- Pull Request Comments: For code review discussions

### Meeting Cadence
The project does not currently have regular meetings. Discussions happen asynchronously through GitHub.

## Release Process

See `governance/RELEASE_GOVERNANCE.md` for detailed release procedures.

## Changes to Governance

Changes to this governance document require consensus among maintainers.
