# Dragon Language Bytecode Execution

## Status: Implementation-defined (based on current VM implementation)

This document describes how Dragon bytecode is executed by the Virtual Machine (VM).

## Virtual Machine Overview

The Dragon VM is a stack-based virtual machine that executes bytecode instructions generated by the compiler. It manages the execution stack, call stack, variable scopes, and handles control flow, function calls, and exception handling.

## Execution Engine

The main execution loop is in `src/engine/vm.rs` in the `execute_chunk` function (or similar). The VM operates in a fetch-decode-execute cycle:

1. **Fetch**: Get the next instruction based on the instruction pointer (IP)
2. **Decode**: Determine what operation to perform
3. **Execute**: Perform the operation, updating the VM state
4. **Repeat**: Continue until a Halt instruction or return from main

## Stacks

The VM uses several stacks:

### Operand Stack
- Stores intermediate values during expression evaluation
- Most instructions pop their operands from this stack and push results back
- Grows and shrinks during expression evaluation

### Call Stack
- Tracks function calls
- Each entry contains:
  - Return address (where to resume after function returns)
  - Previous frame pointer
  - Function context
- Used for implementing function calls and returns

### Variable Stack/Frame
- Stores local variables and parameters for the current function
- Variables are accessed by offset in the current frame
- Each function call gets its own frame

## Instruction Execution

Each instruction modifies the VM state in a specific way:

### Stack Manipulation Instructions
- `LoadConst`: Pushes a constant value onto the operand stack
- `LoadVar`: Pushes the value of a variable (from current frame) onto the stack
- `StoreVar`: Pops a value from the stack and stores it in a variable
- `Pop`: Removes the top value from the stack
- `Dup`: Duplicates the top value on the stack

### Arithmetic and Logic Instructions
- Binary operations (`BinaryOp`): Pop two values, apply operation, push result
- Unary operations (`UnaryOp`): Pop one value, apply operation, push result

### Control Flow Instructions
- `Jump`: Sets IP to target address (unconditional branch)
- `JumpIfFalse`: Pops value, if falsy sets IP to target, otherwise continues
- `JumpIfTrue`: Pops value, if truthy sets IP to target, otherwise continues
- `JumpIfNotNull`: Pops value, if not null sets IP to target, otherwise continues

### Function Instructions
- `MakeClosure`: Creates a function closure object and pushes it onto the stack
- `Call`: Pops function and arguments, creates new frame, pushes return address, jumps to function
- `Return`: Pops return value, restores previous frame and IP, pushes return value onto caller's stack

### Object Instructions
- `GetAttr`: Pops object, pushes value of named attribute
- `SetAttr`: Pops value and object, sets attribute on object
- `GetIndex`: Pops index and object, pushes element at index
- `SetIndex`: Pops value, index, and object, sets element at index

### Exception Handling
- `PushTry`: Pushes exception handler information onto exception stack
- `PopTry`: Pops exception handler information (when exiting try block normally)
- `Raise`: Pops exception value and begins exception unwinding
- `EnterCatch`: Binds caught exception to variable and resumes execution in catch block

## Memory Management

### Heap Allocation
- Objects, arrays, strings, and closures are allocated on the heap
- The VM interfaces with the garbage collector (`src/engine/gc.rs`)
- Memory is automatically reclaimed when objects are no longer reachable

### Stack Allocation
- Function frames and operand stack values are stored in stack memory
- Automatically managed by function call/return and expression evaluation

## Execution Examples

### Simple Expression: `1 + 2`
Bytecode:
```
LoadConst(Number(1.0))
LoadConst(Number(2.0))
BinaryOp(Add)
```

Execution:
1. Push 1.0 onto stack: [1.0]
2. Push 2.0 onto stack: [1.0, 2.0]
3. Pop 2.0, pop 1.0, compute 1.0 + 2.0 = 3.0, push 3.0: [3.0]

### Function Call: `add(2, 3)`
Assuming `add` is a function that adds two parameters:
Bytecode for call:
```
LoadConst(Number(2.0))
LoadConst(Number(3.0))
LoadVar("add")  // or however function is referenced
Call(2)
```

Execution (simplified):
1. Push 2.0: [2.0]
2. Push 3.0: [2.0, 3.0]
3. Push function object: [2.0, 3.0, <func add>]
4. Call: pops 2 args and func, creates new frame, jumps to add function
5. In add function: LoadVar for params, BinaryOp(Add), Return
6. Return value pushed onto caller's stack

## Control Flow Examples

### If Statement: `if condition { ... }`
Bytecode (simplified):
```
<condition evaluation>
JumpIfFalse(target)  // jump to after if block if falsy
<if body>
Jump(end_target)     // jump past else block (if exists)
target:              // else block or after if
<else body>          // if present
end_target:
```

### Loop: `while condition { ... }`
Bytecode (simplified):
```
loop_start:
<condition evaluation>
JumpIfFalse(exit_target)  // exit loop if falsy
<body>
Jump(loop_start)          // repeat loop
exit_target:
```

## Implementation Notes

1. **Instruction pointer**: The VM maintains an instruction pointer (IP) that tracks the next instruction to execute.

2. **Frame management**: Each function call creates a new stack frame with space for locals and parameters.

3. **Exception handling**: Uses a separate exception stack to track try/catch frames.

4. **Garbage collection**: The VM periodically checks if garbage collection is needed and triggers it.

5. **Built-in functions**: Some operations (like I/O) are implemented as built-in functions rather than bytecode.

6. **Debugging**: Line number tracking allows the VM to report errors with source location.
